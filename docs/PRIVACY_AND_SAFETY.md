# ONE and aWake — Privacy and Safety

## Privacy Commitments

ONE is built on data visibility and user agency. A reflection is not saved until the user chooses to save it. Online aWake chat does not become active until the user accepts a clear statement that their submitted message and recent chosen context will be sent to the online model service for a response.

| Control | User-visible behavior |
|---|---|
| Local-first workspace | Reflections, plans, language choice, and saved chat records remain on the device by default. |
| Online consent | The aWake tab presents a consent gate before the first online request. |
| Local chat deletion | The user can clear local chat history in aWake or Vault. |
| Future-use control | The user can turn off future online aWake use in Vault. |
| Full reset | The user can remove all local reflections, local messages, and consent settings. |

## Safety Position

aWake is a reflection-oriented assistant, not a clinician, lawyer, financial adviser, or autonomous decision-maker. It is instructed not to diagnose, pressure, shame, imply unavailable memory, or claim it has taken external actions. For high-stakes situations, it should communicate uncertainty and encourage appropriate professional or immediate safety support.

## Public Repository Exclusions

This repository is intentionally public-safe. It excludes environment files, live credentials, device-local workspace content, database files, runtime logs, build artifacts, and restricted Cloud Computer archives. A public repository must never be treated as a storage location for secrets or private user material.
